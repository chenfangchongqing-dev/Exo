## 已有修复与本轮修正

| 项目 | 核查结果 |
| --- | --- |
| 首次启动 | 已有版本在「Commencer la visite」点击中同步调用第一句朗读，本轮保留。没有等待语音列表加载，也没有添加静音音频“解锁”。 |
| 声音开关 | 已有版本明确显示开关状态，本轮保留。主动点击「Écouter / Réessayer」也会开启声音，避免用户点击试听却被静音状态直接忽略。 |
| 替换朗读 | 已有版本取消播放后等待 100 毫秒；原延时任务未保存、未失效。本轮保存定时器并核对任务代次，连点、关声、重启、打开声音设置均会取消旧任务。 |
| 尚未启动时的重播 | 若尚无 start 事件，取消后显示「Réessayer」，要求一次新的点击；避免第一次实际启动落到延时回调里。观察过 start 后的替换保留 100 毫秒等待。 |
| 法语声音 | 每次开始播放重新获取列表，并继续监听 voiceschanged。列表为空可以是延迟或浏览器隐藏，不能断言设备没有安装法语声音。保留 fr-FR 尝试及明确提示。 |
| 声音选择 | 自动选择优先本地法语声音，降低远程声音加载失败风险；用户指定的声音仍优先。使用所选声音的语言标签。 |
| 连续对话 | 正常结束才播放下一句。错误会中止待播队列并提示重试，防止静默跳过学习内容。旧话语的迟到回调不能影响新话语。 |
| 卡住与异常 | 8 秒未收到 start/end/error 则提示未启动；收到 start 后，超时上限按文本长度设置，至少 30 秒。二者均清除卡住的队列，不无限自动重试。 |
| 后台与重启 | 离开页面会停止并清空待播任务；返回后由用户点击重试。重新开始不会继承旧对话。 |
| 能力缺失 | 同时检查合成接口与话语构造器；不支持时明确提示，文本对话仍可用。 |

3D 场景、法语教学材料、点餐与游戏推进逻辑保持原样。`functions/_middleware.js` 没有修改；咖啡馆三个地址别名的 GET/HEAD 均仍免密码。未接入语音服务或增加网络音频依赖。

## 已完成的程序验证

从仓库根目录执行：

```sh
node --test tests/cafe-speech.test.cjs
```

25 项模拟 API 回归测试通过：同步启动、顺序对话、迟到回调、缺少启动/结束事件、多种错误、抛出异常、空/迟到声音列表、本地优先与手动选择、缺少接口、静音后的主动试听、快速连点、关闭再开启声音、切到后台、重新开始及三个角色试听。测试也解析了完整脚本。

桌面浏览器补充检查：远程 Chrome 无法启动 WebGL，故仅在临时预览副本中隐藏图形错误遮罩，检查了声音控件。该环境未检测到法语声音，首次尝试和重试均明确显示失败提示；声音设置及说明正常显示。此预览改动未写入交付源码，不构成 3D 场景或手机声音测试。

另已逐段比较 3D 实现、任务与教材数据、对话交互函数，未改变；无重复 HTML ID、无差异空白错误。使用原始中间件验证了三个公开地址各自的 GET/HEAD 共六种请求，并检查其他 Events 路径仍受保护。

**这些结果仅证明代码逻辑在模拟事件下符合预期。未取得真实 iPhone Safari 实际听音通过证据。浏览器的 start/end 事件不能证明扬声器发声，也不能判断音量、蓝牙输出或实际发音语言。**

## 手机验证步骤

先记录手机型号、iOS 版本、浏览器及是否在微信内打开。先用 Safari 直接打开上述入口，刷新页面，确认 🎧 中已有新版声音说明。检查媒体音量与蓝牙输出。

| 操作 | 合格表现 |
| --- | --- |
| 新开页面，点「Commencer la visite」一次 | 听到 Luc 完整问候；首次播放不需要先关声再开声。 |
| 点 🎧，依次试听 Luc、Élise、Vous | 三个样句都完整可听。只有一种法语声音时，音色相同属于正常限制。记录所显示的声音名称。 |
| 关闭设置，重听问候，然后在播放中选「Une table pour une personne…」 | 按顺序听到剩余问候、学习者选句、服务员回应；不叠音、不漏句。 |
| 继续点餐、收餐、结账，至少走完五轮 | 每轮朗读都能继续；菜单的 ♫ 可重听点餐句。 |
| 快速点重听三次，或在 100 毫秒内切换试听角色 | 最终只重播最后选中的内容；没有旧句稍后插入。若首次播放尚未启动，按提示再点「Réessayer」。 |
| 播放中关闭声音，立即重新开启 | 关闭时停止；开启时只有当前句，不恢复已取消的旧队列。 |
| 静音时点击「Écouter」 | 声音自动开启并尝试播放。 |
| 播放中切到后台或锁屏，等待十秒，再回来 | 不自动补读过期队列；显示中断提示。点「Réessayer」或对话框重听可恢复。 |
| 再次开始游戏 | 只听到新一轮问候，没有上一轮遗留对话。 |
| 换成离线状态，再试听已安装的本地声音 | 若系统向浏览器提供可离线使用的声音，应能播放。远程声音失败时应给出提示，不应一直无反应。 |

若页面显示未检测到法语声音，先打开 🎧 查看说明；在 iPhone「设置 → 辅助功能 → 朗读内容 / 朗读与语音 → 声音」中检查法语声音（名称随 iOS 版本变化），下载后返回网页再次试听。系统下载完成不等于 Safari 已向网页提供声音，应以该页实际试听为准。

若仍静音，记录：失败发生在哪一句、页面提示原文、法语声音名称、是否能用系统朗读功能读出法语、是否连接耳机/蓝牙。微信等内置浏览器需单独验证，其结果不能替代 Safari 结果。

## 依据

- [WebKit SpeechSynthesis 实现](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/Modules/speech/SpeechSynthesis.cpp)：用户手势限制、可能隐藏语音列表、取消与回调处理。不能据此断言所有已发布 iOS 版本行为一致。
- [Web Speech API 规范](https://webaudio.github.io/web-speech-api/#tts-section)：语音队列、事件和错误接口。
- [Apple 语音设置说明](https://support.apple.com/en-in/111798)：系统声音选择、下载与辅助功能入口。设置项名称因版本而异。
