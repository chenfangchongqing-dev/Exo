# Exo · Passeport culturel（法语探索护照）
> 设计版本 v0.1，2026-11-19 · 教学游戏平台积分机制草案  
> 定位：将任务化 FLE 学习场景中的反馈、主题成就和自愿兑换统一起来。**学习反馈优先、兑换激励其次。**

## 一、产品体验

**学生端主视觉**：Exo「文化护照」(Passeport culturel)，精致的小型收集册、主题印章、阶段性称号，避免大面积排行榜和机械刷题。
- 每次符合条件的学习任务成功后，弹出轻量提示，例如：`🤝 交际礼仪 +1` / `✦ 文化印章 +1` / `经验 +10 XP`，动画不超过 600ms。
- 游戏顶部显示小型“护照”按钮，打开后看到本主题已收集的印章、XP、待探索卡片和称号。
- 文化阅读与对话交互各有自己的触发规则；**奖励不使用语音朗读**，延续现有“语音只用于真实台词”的原则。
- 可设置主题章（3/3 完成），如 `Au café · Explorateur du Flore`。收集进度不能取代学生真正的语言产出评价。

### 当前已实现的可体验版本（Café de Flore）
- 场景：`/Events/au-cafe-de-flore/`。
- Les bonnes manières → **交际礼仪 +1** / Savoir-vivre。
- Le portable au café → **公共关怀 +1** / Respect d’autrui。
- Le Café de Flore → **文化探索 +1** / Curiosité culturelle。
- 每张卡**首次答对**可得 **1 枚文化印章 +10 XP**；同一浏览器重复答对不再增发。
- 一章最多 3 枚印章、30 XP，达成 1 / 2 / 3 枚时分别显示阶段称号。
- **当前仅在浏览器 localStorage 保存**；可在同一域名、同一浏览器下留存，但不同设备、隐私浏览窗口、清空数据后可能消失或重置。数据**不能作为实物兑换凭证**；浏览器数据容易修改。

## 二、三种进度，避免混淆

| 体系 | 含义 | 发放规则 | 可用于兑换？ |
|---|---|---|---|
| 主题能力印章（tampons thématiques） | 在**某次任务中**展示过的特定知识或交际策略，例如“识别礼貌表达” | 题目首次正确、或通过明确评价标准 | 可作为教师核验后的资格数量 |
| 探索经验（XP） | 可视化进度与参与轨迹，鼓励探索 | 低权重、封顶；不依据频繁点击或答题速度 | 默认不作为实体兑换货币 |
| 已核验兑换券（crédits validés） | 教师确认可兑换的权益 | 仅服务器端根据有据可查的事件与规则发放 | **可以**，由教师审核与核销 |

**“公民责任感 +1”属于价值/人格层面的较强推断。** 对单道礼貌选择题，推荐使用“交际礼仪 +1”或“公共关怀 +1”，反映完成的学习任务，不给学生贴人格标签。

## 三、扩展为 Exo 全平台

以学习主题为单位组织“赛季卡册”，包括场景化游戏、阅读、听力、口语、写作和语言资源中心。建议逐步推出以下主题：

| 主题卡册 | 可接入示例 | 主题印章（示例） |
|---|---|---|
| Au café · 咖啡馆交际 | 点餐对话 / 礼貌 / 文化卡 | 交际礼仪、公共关怀、文化探索 |
| Le bonheur · 幸福 | 观点表达、论据、语言修订 | 论证思维、语言组织、自主修订 |
| Apparence · 外表 | 文化差异讨论、观点调节 | 文化敏感性、表达得体、观点辨析 |
| Planète · 地球 | 生态阅读、行动任务 | 信息判断、环境观察、公共参与 |

提醒：口语“说了一句”不自动代表口语能力达标。未来需要明确任务要求与可观察证据（是否作出合适应答、是否完成沟通目标、是否修订表达等）；写作同理。

### 单元内与跨单元呈现
- **单元页**：个人集章、当前任务、解锁称号和复习入口。
- **Exo 主页**：概览本学期的主题卡册，不以排行榜压迫学生。
- **教师端**：按班级、主题、任务核验发放情况，支持撤销误发、异常记录查阅与 CSV 导出。
- **可选合作任务**：全班共同探索的集体进度，弱化单纯个人竞争；不惩罚缺课、学习节奏慢和使用无障碍辅助工具的同学。

## 四、奖励与兑换（建议规则，非现行承诺）

学校教学活动经费、发放资格与奖品清单须由教师/学院另行确定后才上线兑换按钮。以下为**示意档位**：

| 已核验印章 | 示例奖励 | 处理方式 |
|---:|---|---|
| 3 | 主题数字称号 / 特别学习素材 | 可自动解锁 |
| 8 | 课程主题贴纸（少量、低成本） | 教师核验后线下领取 |
| 18 | 法语主题书签 / 文具 | 依据库存核销 |
| 30 | 主题文化活动优先预约 / 小额奖品 | 明确库存、预算、公平规则 |

设计原则：
1. 不把普通小测的分数直接换算为课程总评成绩；如需计入课程评价，应另定评分依据与补偿机制。
2. 同一任务/版本/学期只能领取一次，重复练习可以获得反馈，不重复兑换。
3. 高价值奖励和学业评价必须有**服务器记录 + 教师校核**，防止清空浏览器数据、修改 localStorage 或重复调用接口刷奖励。
4. 定义替代完成路径，避免因设备、网络、身心障碍或家庭经济条件不同而影响获得机会。
5. 不采用诱导付费、盲盒式随机付费、连续登录惩罚或逼迫分享成绩的玩法。

## 五、未来正式版技术方案

当前 Cloudflare Pages 的课程密码是**共享课程访问码**，不能识别每位学生，因而无法可靠实现跨设备个人累计。必须另做个人身份层：

**身份**：给每位学生提供一次性绑定码或学校单点登录，保存匿名学习者 ID；不要把学号、实名、手机号公开写入前端。

**统一事件**：所有模块通过一个 `award` 接口上报 `learner_id`（由服务端身份确定）、`module_id`、`unit_id`、`task_id`、`rule_version`、`attempt_id` 与任务证据。由服务器判断是否满足条件，不接受浏览器自报的最终积分数额。

**数据层**：Cloudflare Pages Functions + D1（方案建议，尚未创建数据库），最少包括：
- `learners`：匿名 ID、班级/课程、身份绑定状态；
- `task_rules`：哪些任务产生什么印章、何时生效、上限；
- `award_events`：不可重复的事件键（如 learner + task + rule version），唯一约束，服务器时间与教师复核状态；
- `redemptions`：兑换申请、审批者、发放时间、物品库存与核销状态；
- `audit_log`：每次人工调整、撤销、核销有记录。

**原子性与防作弊**：奖励记账放到服务端事务，唯一约束/幂等键；发放与库存变更必须原子处理。不能信任浏览器可编辑的 localStorage、请求中的 XP 或随意传入的 student_id。

**隐私与教学伦理**：数据最小化、设定保存期限；学生可查看自己的奖励和评分依据，可申请复核；个人排行榜默认关闭。正式部署前明确告知记录用途与范围。

## 六、实施顺序与验收标准

1. **已完成 · 咖啡馆 MVP**：3 个文化问答、恰当的主题印章、答对微动画、护照入口、本设备内防重复发放。
2. **下一阶段 · 统一学生身份 + 服务端奖励账本**：完成认证、跨设备同步、唯一发放、教师核验；在此之前不开放兑换。
3. **再下一阶段 · Exo 其他模块接入**：定义每个任务的有效完成证据，再逐个接入同一 API，而不是复制多套独立积分规则。
4. **最后 · 兑换试点与效果评估**：教师端上架奖品、库存、申请与核销；追踪完成率、持续学习、重复练习质量、公平性与学生反馈。

**核心验收**：同一题重复答对不加分；刷新保留本地演示记录；只有正确答案发奖；无声奖励反馈不干扰法语对话；移动端可查看护照；正式版禁止客户端伪造兑换余额。
